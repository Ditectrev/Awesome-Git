## Introduction to Git

[Git](https://git-scm.com/) is how you record project history, work in parallel, and review changes without overwriting each other. This chapter defines the job, names the problem version control solves, separates [Git](https://git-scm.com/) from [GitHub](https://github.com/) and other hosts, and shows how we practice in the browser so you do not need [Git](https://git-scm.com/) installed on your machine.

### What is [Git](https://git-scm.com/)?

**[Git](https://git-scm.com/)** is a distributed version control system (DVCS). A version control system tracks changes to files over time so you can answer four working questions: what changed, who changed it, when, and—if the commit message is useful—why. Distributed means a complete copy of a repository can hold the full history, not only a copy that lives on one central server. We will unpack that design in Core Principles of Git. For this chapter, treat [Git](https://git-scm.com/) as the engine that stores snapshots of a project.

The official home is [git-scm.com](https://git-scm.com/). The [Git project](https://git-scm.com/about) describes [Git](https://git-scm.com/) as fast, widely used, and released as free and open source software. The [Git documentation](https://git-scm.com/doc) is the canonical reference for the tool itself. [GitHub Docs: About Git](https://docs.github.com/en/get-started/using-git/about-git) is how the same engine shows up when you work on a host.

**[Git](https://git-scm.com/) is software, not a website.** You can run it from a command line, from a desktop app, or through a host's web UI. This book uses the web UI first. The same snapshots, commits, and branches are [Git](https://git-scm.com/) objects either way. The buttons you click on [GitHub](https://github.com/) still create [Git](https://git-scm.com/) history.

A few words we will keep using:

- **Repository (repo):** the project plus its history. On [GitHub](https://github.com/), a repository is the page you open. Under the hood it is a [Git](https://git-scm.com/) database of snapshots.
- **Commit:** a saved snapshot with a message, an author, and a parent (or parents). You will make your first commit in the [GitHub](https://github.com/) web editor in Repositories, Files, and Commits.
- **Branch:** a movable name for a line of work. Branches and Merging is the chapter that makes this concrete.
- **Host:** a service that stores [Git](https://git-scm.com/) repositories and adds a web UI, permissions, and review. Our host is [GitHub](https://github.com/).

**What [Git](https://git-scm.com/) is not:**

- Not [GitHub](https://github.com/). [GitHub](https://github.com/) hosts [Git](https://git-scm.com/) repositories and adds collaboration on top. You can use [Git](https://git-scm.com/) without [GitHub](https://github.com/). You cannot use [GitHub](https://github.com/) as version control without [Git](https://git-scm.com/) running for you.
- Not a backup product by itself. History helps you recover old versions of tracked files. It does not replace a backup of secrets, untracked files, or the host account.
- Not a deploy button. Some hosts wire [Git](https://git-scm.com/) to CI and hosting. This book stays on version control and collaboration. Host CI as a merge gate is Appendix F, not the main path.

[Git](https://git-scm.com/) started as the tool that tracks the [Linux kernel](https://www.kernel.org/). That origin story belongs in History and Evolution of Git. You do not need that history to start clicking in the browser. You do need the distinction we make next: version control is the job, [Git](https://git-scm.com/) is the tool we use for it, and [GitHub](https://github.com/) is where we practice.

### What Problem Version Control Solves

Without version control, a project is a folder that only the latest save can describe. People copy files, email attachments, and rename drafts until nobody can answer "which copy is true?" Version control replaces that mess with a shared history you can inspect, branch, and review.

**The daily problems version control is for:**

1. **Overwriting**
   - Two people edit the same file. The last save wins. The other person's work disappears.
   - Version control records both lines of work so you can combine them, or at least see the conflict instead of silently losing a save.
2. **No latest copy**
   - Folders named `final`, `final-v2`, and `final-FINAL` are not history. They are guesses.
   - A repository has a default branch that points at the current agreed snapshot, plus older commits you can still open.
3. **No audit trail**
   - When something breaks, you need who changed it, when, and in which commit.
   - [Git](https://git-scm.com/) stores that on every commit. On [GitHub](https://github.com/) you will read it on the Commits page, not in a spreadsheet of filenames.
4. **Fear of changing things**
   - If the only copy is the live file, every edit feels risky.
   - Commits let you take a snapshot before you try something. Branches let you try it without touching the default branch. Revert on [GitHub](https://github.com/) (Conflicts and History Repair in the Browser) is how you undo a published commit without pretending it never happened.
5. **Review is guesswork**
   - Asking a teammate to "look at the folder" does not scale.
   - A pull request on [GitHub](https://github.com/) is a review of a [Git](https://git-scm.com/) diff: the exact commits you want to merge, with comments on the lines that changed.

**What you get once history exists:**

- **Snapshots, not a pile of copies.** [Git](https://git-scm.com/) records the state of tracked files at each commit. Core Principles of Git explains why those snapshots are not "a list of diffs" even though [GitHub](https://github.com/) shows you a diff view.
- **Parallel work.** Branches isolate a feature, a fix, or an experiment. You merge when the work is ready. That is the normal [GitHub](https://github.com/) flow we will click through later.
- **Attribution.** Commits carry an author. Review comments on [GitHub](https://github.com/) sit on those commits.
- **Recovery with a record.** You can go back to an older snapshot. You can also see the commits you are leaving behind, which a restored zip file never shows.

Version control is the job. [Git](https://git-scm.com/) is one tool that does that job. Older centralized systems such as [Apache Subversion](https://subversion.apache.org/) and other distributed tools such as [Mercurial](https://www.mercurial-scm.org/) solved overlapping problems with different designs. We are not running those tools. History and Evolution of Git is where we place [Git](https://git-scm.com/) on that timeline. The working rule for this book: if you need history, review, and parallel work, you need a version control system. We teach that system as [Git](https://git-scm.com/), practiced on [GitHub](https://github.com/).

A shared drive, a chat attachment, or a "please use this file" email is not version control. Those channels move bytes. They do not give you a graph of commits you can branch, review, and revert.

### [Git](https://git-scm.com/) vs [GitHub](https://github.com/) vs Other Hosts

Three layers show up in every later chapter. Mixing them up is the most common beginner trap, so we separate them now.

**1. [Git](https://git-scm.com/) — the version control system**

- Stores repositories, commits, branches, and tags.
- Official site: [git-scm.com](https://git-scm.com/). Docs: [Git documentation](https://git-scm.com/doc).
- Does not require [GitHub](https://github.com/). A repository on a USB drive, a company server, or another host is still [Git](https://git-scm.com/) if it uses that format.

**2. A [Git](https://git-scm.com/) host — the service that stores repositories and adds a web UI**

- **[GitHub](https://github.com/)** is our host. It stores [Git](https://git-scm.com/) repositories and adds issues, pull requests, permissions, and the pages we will click. Product: [github.com](https://github.com/). Docs: [GitHub Docs](https://docs.github.com/). Free accounts are enough for the main path; plans are on [GitHub Pricing](https://github.com/pricing).
- The host runs [Git](https://git-scm.com/) for you when you edit in the browser. You still produce [Git](https://git-scm.com/) commits. You are not using [GitHub](https://github.com/) instead of [Git](https://git-scm.com/). You are using [Git](https://git-scm.com/) through [GitHub](https://github.com/).

**3. Collaboration features on top of [Git](https://git-scm.com/)**

- Pull requests, reviews, checks, and branch rules are host features. They describe [Git](https://git-scm.com/) history; they are not extra [Git](https://git-scm.com/) object types.
- [GitHub flow](https://docs.github.com/en/get-started/using-github/github-flow) is the usual loop we will practice: branch, commit, open a pull request, review, merge. That loop is a [GitHub](https://github.com/) workflow over [Git](https://git-scm.com/) branches.

**Other hosts (mention only — not a lab):**

The same [Git](https://git-scm.com/) repositories can live on more than one product. These four show up often at work. They speak [Git](https://git-scm.com/). Their web UIs look similar to [GitHub](https://github.com/) (repositories, merge requests or pull requests, permissions). We name them so you can recognize them. We do not open a second classroom on them.

- **[GitLab](https://gitlab.com/)** — [gitlab.com](https://gitlab.com/) (self-managed [GitLab](https://about.gitlab.com/) exists too). Merge requests are the review object that maps to [GitHub](https://github.com/) pull requests.
- **[Bitbucket](https://bitbucket.org/)** — [bitbucket.org](https://bitbucket.org/). Pull requests over [Git](https://git-scm.com/) repositories.
- **[Codeberg](https://codeberg.org/)** — [codeberg.org](https://codeberg.org/). A public [Git](https://git-scm.com/) host with a forge-style web UI.
- **[Azure Repos](https://azure.microsoft.com/en-us/products/devops/repos)** — [Azure Repos](https://azure.microsoft.com/en-us/products/devops/repos) in [Azure DevOps](https://azure.microsoft.com/en-us/products/devops). [Git](https://git-scm.com/) repos plus a web editor and pull requests.

Collaboration, Access, and Other Git Hosts repeats this as a one-line tour. Additional Resources and Reading Materials has Other Git Hosts for pointers. Neither place is a second lab. If your job uses [GitLab](https://gitlab.com/) or [Bitbucket](https://bitbucket.org/), the [Git](https://git-scm.com/) model you learn here still applies. The button labels will differ. The commits will not.

**Working rule:** when we say [Git](https://git-scm.com/), we mean the version control system. When we say [GitHub](https://github.com/), we mean the host where you click. When we say another host, we mean "same [Git](https://git-scm.com/), similar web UI, not our lab."

### Why This Book Does Not Require [Git](https://git-scm.com/) Installed Locally

Most [Git](https://git-scm.com/) books start by installing a binary, fixing `PATH`, and setting SSH keys. That is a real skill. It is also the step that stops people before they have seen a commit. We do not start there.

**Why the main path stays in the browser:**

- **The host already runs [Git](https://git-scm.com/).** Creating a file on [GitHub](https://github.com/) and clicking Commit changes writes a [Git](https://git-scm.com/) commit. You do not need a local `git` program for that. The [GitHub](https://github.com/) [web file editor](https://docs.github.com/en/repositories/working-with-files/managing-files/editing-files) is enough for one-file commits.
- **[github.dev](https://docs.github.com/en/codespaces/the-githubdev-web-based-editor) is a full editor without a laptop clone.** It is [Visual Studio Code](https://code.visualstudio.com/) for the Web. Official docs: [Using VS Code for the Web from GitHub](https://docs.github.com/en/codespaces/the-githubdev-web-based-editor) and [VS Code for the Web](https://code.visualstudio.com/docs/editor/vscode-web). You must be signed in to [GitHub](https://github.com/). The editor talks to the repository from the browser instead of copying it onto your disk.
- **[Learn Git Branching](https://learngitbranching.js.org/) is a visual sandbox.** You will use it when we need you to *see* commits and branches. It runs in the browser. It does not install [Git](https://git-scm.com/) and it does not touch your [GitHub](https://github.com/) account.
- **[GitHub Codespaces](https://github.com/features/codespaces) is optional.** A codespace is a cloud machine with a terminal and [Git](https://git-scm.com/) already there. We name it so [GitHub](https://github.com/)'s "Open in codespace" button is not a mystery. Docs: [GitHub Codespaces](https://docs.github.com/en/codespaces). It is never required. Skip it unless a later chapter marks it optional.
- **Local install is a later, skippable section.** Additional Resources and Reading Materials has Git on Your Own Machine: when the command line becomes worth it, how to install [Git](https://git-scm.com/), and how web buttons map to commands. The course can skip that entire section. You can finish the main chapters without it.

**What you avoid by not installing yet:**

- Operating-system differences in how you install a command-line tool.
- Credential helpers, SSH keys, and personal access tokens before you have made a commit.
- A local clone that drifts from [GitHub](https://github.com/) while you are still learning what a commit is.

**What the browser cannot do (so we do not pretend):**

- The basic [GitHub](https://github.com/) web editor has no force-push button. Force-push (`git push --force`, `--force-with-lease`) is Appendix A, not the normal workflow.
- [GitHub](https://github.com/) has no `git restore` and no stash. Discarding uncommitted edits in the web editor is the browser analog; restore, stash, and clean are Appendix G.
- [Git](https://git-scm.com/) aliases (`git config alias.…`) have no [GitHub](https://github.com/) web UI. They live under Additional Resources.

You are not missing "real [Git](https://git-scm.com/)" by working in the browser. You are using [Git](https://git-scm.com/) through the host. When a later chapter needs a terminal, we will say so and point at [Learn Git Branching](https://learngitbranching.js.org/), an optional [GitHub Codespace](https://github.com/features/codespaces), or Git on Your Own Machine. Until then, do not install anything.

### How We Practice in the Browser

This section is a map, not a lab. You will create a [GitHub](https://github.com/) account in The Browser Lab. You do not need to click through a repository yet.

**What you need for the main path:**

- A web browser.
- Starting in The Browser Lab: a free [GitHub](https://github.com/) account ([Creating an account on GitHub](https://docs.github.com/en/get-started/start-your-journey/creating-an-account-on-github)).
- No local [Git](https://git-scm.com/) binary. No paid [GitHub](https://github.com/) plan. No [GitLab](https://gitlab.com/), [Bitbucket](https://bitbucket.org/), [Codeberg](https://codeberg.org/), or [Azure Repos](https://azure.microsoft.com/en-us/products/devops/repos) account.

**The three practice surfaces we will keep naming:**

**[GitHub](https://github.com/)**

- **Primary function:** store the repository and click the real workflow: files, commits, branches, pull requests, reviews, conflict editor, releases.
- **When we send you here:** anything that must land in a real repository. Creating a repo, editing a file, opening a pull request, merging, reverting.
- **How you open it:** [github.com](https://github.com/). Docs start at [GitHub Docs](https://docs.github.com/).
- **One-file edits:** the [web file editor](https://docs.github.com/en/repositories/working-with-files/managing-files/editing-files) on [GitHub](https://github.com/) itself.

**[github.dev](https://docs.github.com/en/codespaces/the-githubdev-web-based-editor)**

- **Primary function:** [Visual Studio Code](https://code.visualstudio.com/) in the browser for multi-file edits, search, and a Source Control view, still without installing [Git](https://git-scm.com/).
- **When we send you here:** more than one file, or when the [GitHub](https://github.com/) file editor is too small for the change.
- **How you open it:** on a [GitHub](https://github.com/) repository, press `.` (same tab) or `>` (new tab), or change `github.com` to `github.dev` in the URL. You must be signed in. Docs: [Using VS Code for the Web from GitHub](https://docs.github.com/en/codespaces/the-githubdev-web-based-editor), [VS Code for the Web](https://code.visualstudio.com/docs/editor/vscode-web).
- **What it is not:** it is not [GitHub Codespaces](https://github.com/features/codespaces). No cloud VM is required. Extensions that run here without local [Git](https://git-scm.com/) belong in The Browser Lab and in Additional Resources; we will not install them in this chapter.

**[Learn Git Branching](https://learngitbranching.js.org/)**

- **Primary function:** a visual sandbox. You type commands that *look like* the [Git](https://git-scm.com/) command line, and the commit graph updates on screen.
- **When we send you here:** when you need to see branches, merges, and later rebase, without touching a [GitHub](https://github.com/) repository.
- **How you open it:** [learngitbranching.js.org](https://learngitbranching.js.org/). Source: [pcottle/learnGitBranching](https://github.com/pcottle/learnGitBranching).
- **What it is not:** those commands do not install [Git](https://git-scm.com/) on your computer and they do not push to [GitHub](https://github.com/). The sandbox is a toy repository for your eyes. When we want a real commit, we go back to [GitHub](https://github.com/).

**Optional, never required: [GitHub Codespaces](https://github.com/features/codespaces)**

- A codespace is a cloud machine in the browser with a terminal and [Git](https://git-scm.com/) already installed. Docs: [GitHub Codespaces](https://docs.github.com/en/codespaces).
- Use it only when a later chapter says you need a real terminal and you do not want Git on Your Own Machine. Skip it on the main path.

**Working loop we will repeat:**

1. Read the chapter (this book is the lesson).
2. When the text says to record history in a real project, use [GitHub](https://github.com/) — web editor for one file, [github.dev](https://docs.github.com/en/codespaces/the-githubdev-web-based-editor) for many files.
3. When the text says to *see* the graph, use [Learn Git Branching](https://learngitbranching.js.org/).
4. Do not install local [Git](https://git-scm.com/) unless you choose Additional Resources. Do not open [GitLab](https://gitlab.com/), [Bitbucket](https://bitbucket.org/), [Codeberg](https://codeberg.org/), or [Azure Repos](https://azure.microsoft.com/en-us/products/devops/repos) as a classroom.

The next two chapters stay on reading: History and Evolution of Git, then Core Principles of Git. The first click-through lab is The Browser Lab.

### Summary: Introduction to Git

We covered what [Git](https://git-scm.com/) is (a distributed version control system, not a website), what problem version control solves (history, parallel work, review, recovery), and how [Git](https://git-scm.com/) differs from [GitHub](https://github.com/) and from other hosts ([GitLab](https://gitlab.com/), [Bitbucket](https://bitbucket.org/), [Codeberg](https://codeberg.org/), [Azure Repos](https://azure.microsoft.com/en-us/products/devops/repos) — same [Git](https://git-scm.com/), similar web UI, not our lab). You do not need [Git](https://git-scm.com/) installed locally: we practice on [GitHub](https://github.com/), [github.dev](https://docs.github.com/en/codespaces/the-githubdev-web-based-editor), and [Learn Git Branching](https://learngitbranching.js.org/), with [GitHub Codespaces](https://github.com/features/codespaces) optional. You now have the vocabulary we will use for the rest of the book. Next, we will walk through History and Evolution of Git.
